The family (register §5's re-aimed target, measured this session):
the typed backend kept every invoke argument in a fresh heap
`Vec<Value>` per call — `let __a = vec![sN.clone()];` — even though
the arg vec is ONE-SHOT into one of two consumers, both of which take
`&[Value]`:
  - `::j2r_runtime::natives::invoke_exact(..., &__a, crate::j2r_dispatch())`
  - direct compiled-method calls `crate::classes::X::m_yyy(recv, &__a)`
Census on the JAMA typed crate (8 classes, JamaBench): **228 vec
arg sites** (67 empty `vec![]`, 161 non-empty up to 4 args), every one
verified one-shot (no reuse, no push, no rebinding before the consume;
the `__a` name is reused AFTER the invoke for typed locals — shadowing,
legal). Per call the vec cost: a heap malloc + capacity header + Vec
drop glue + a `Value::clone()` per ref arg (unchanged — GC-root parity:
the clones root exactly as before; only the container changed).

The change (crates/j2r-codegen/src/typed.rs, the three invoke arms —
InvokeVirtual/Interface, InvokeSpecial, InvokeStatic):
  non-empty: `let __a = [args...];`      (a [Value; N] stack array)
  empty:     `let __a: [::j2r_runtime::Value; 0] = [];`
`&[Value; N]` unsized-coerces to `&[Value]` at both consumer shapes —
zero runtime change, zero signature change. Scope: the TYPED backend
only (the default backend's arg vecs are the same shape — registered
as a follow-up candidate, separately measured if taken).
