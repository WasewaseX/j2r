PREMISE CORRECTED BY THE PROBE (the code wins over the register)

The registered text said "Field.get on a static of a compiled class
returns null (discovered en route)". The minimal probe (ReflStatic2:
getDeclaredField on statics int/String/double + .get(null) + the boxed
class names) PASSED byte-identical on the first run — the static path
(ctx.static_get + box_by_desc) already worked; whatever the register
observed was a different shape or fixed by a later wave. The REAL gaps
the probe found, and what this slice lands:

1. **Class.getField(String)** — the public-member search law (OpenJDK
   getField0): own PUBLIC fields first, then the SUPERCLASS chain
   recursively; a non-public same-name field does NOT block the walk
   (the JDK quirk — pinned: Child shadows the inherited public
   PUB_STATIC with a package-private one and getField returns the
   SUPERCLASS field, getDeclaringClass proves it). The
   interface-constants leg of the JDK walk is a registered residual
   (UserClassInfo carries no interfaces table — that lands with the
   getFields/getDeclaredConstructors slice). Miss → NSFE(name); null
   name → plain NPE (oracle-pinned).
2. **Field.getModifiers / Method.getModifiers** — the raw ACC_* masks.
   The metadata now carries them end to end: FieldPlan/MethodPlan gain
   `modifiers` (the classfile's raw access flags at parse time),
   UserField/UserMethod gain `modifiers`, BOTH metadata emitters
   (single-crate emit.rs + partitioned partition.rs) write them, and
   the Field object grew slot 6 (6→7 total slots), the Method object
   slot 4 (4→5).
3. **Field.getDeclaringClass()** — the owner class (needed by the
   inherited-field pin).
4. **The typed getter/setter family** — getInt/getLong/getFloat/
   getDouble/getBoolean/getChar/getShort/getByte + the eight setters,
   with the JDK's widening table (jdk.internal.reflect canConvert: to
   Z/B only themselves; C from B/S; S from B; I from B/C/S; J/F/D the
   widening lattice) and the Temurin-exact wrong-narrow message
   (NarrowMsg oracle): `Attempt to get double field "NarrowMsg.D" with
   illegal data type conversion to int`. The GET widening (getInt on a
   long field etc.) is JDK-exact; the SET cross-kind message follows
   the JDK shape but is not pinned (honest residual — exact-kind sets
   are pinned).
