THE MECHANISM (crates/j2r-codegen/src/peephole.rs, map_prim_rewrites):
a post-verify IR pass recognizing javac's autobox map cores on a
receiver local the CLOSURE LAW proved safe, replacing each with ONE
synthetic instruction (MapPutPrim / MapGetPrim in ir.rs, verifier arms
in verify.rs, both emitters armed — emit.rs direct-native form, typed.rs
unified-push form). The runtime natives (collections.rs): hm_put_prim
stores the RAW prim Value in the node's value slot through hm_put's own
machinery (the key hash/equals dispatch, resize law and modCount are
byte-identical); hm_get_prim unwraps the slot to the prim payload, the
absent key throwing the faithful bare NPE.

THE CLOSURE LAW (why the raw slot is unobservable):
  1. HASHMAP-FRESH: every Store(n) is a `New HashMap; Dup; (consts);
     Invokespecial <init>; Store(n)` creation run.
  2. CONSUMPTION-CLOSED: every Load(n) is a rewritten core's receiver
     (the backward shape walk resolves each core's receiver; any other
     load — argument pass, field store, return, keySet, a non-core
     put/get — refuses the WHOLE local, the faithful path stands).
  Span guards mirror the fill pass: no branch target inside
  (receiver_pc, end_pc), no partially-overlapping exception entry (a
  refusal removes every core of the same local — a refused core keeps
  the boxing path, which must never observe a prim slot).
  Under both rules every slot was written by a rewritten put and every
  read is a rewritten get: the box never materializes, the heap-
  pollution CCE the faithful checkcast would throw is unreachable, and
  the Integer/Long [-128,127] JLS cache law has nothing to preserve.
