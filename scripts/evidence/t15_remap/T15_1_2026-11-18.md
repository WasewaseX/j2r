# T15.1 — the raw-class-transport slice — 2026-11-18

Queue head T15 (the remap stage) opened with the transport slice, PROBE
FIRST: the resolver (`ClassFile::parse`) interprets attributes and drops
what it does not need (LineNumberTable, StackMapTable bodies, unknown
attributes, precise attribute order) — so a parse→serialize round trip
through the RESOLVED model can never be byte-exact. The remap stage needs
the opposite contract, so the slice is a NEW module
(`crates/j2r-classfile/src/remap.rs`) that never touches the proven
resolver path (only `decode_modified_utf8` became `pub(crate)`, a pure
function re-use):

- `RawCpEntry { tag, data }` — the payload AFTER the tag, raw bytes; Utf8
  keeps the raw modified-UTF-8 so exotic constants survive bit-for-bit.
- `RawPool` — 1-based slots, slot 0 `None`, Long/Double second slot
  `None`; `append_utf8` grows the pool without disturbing any index.
- `RawAttribute { name_index, payload }` / `RawMember` / `RawClassFile` —
  everything the reader saw, nothing interpreted.
- `serialize()` — byte-exact writer (law 1).
- `retarget_this_class(new_name)` — the T15 remap primitive, shape (a):
  appends one Utf8, retargets the `this_class` Class entry's name_index,
  moves no other byte.

Vectors (committed `tests/vectors/remap/`, javac 21.0.13): RemapVec1
(primitive fields + string-concat indy bootstrap), RemapVec2 (+ inner
classes, generics Signatures, exception table + StackMapTable,
synchronized, throws), RemapVec3 (record + enum switch + lambda indy +
`"a\u0000b"` C0-80 and a supplementary scalar in the pool) — 8 class
files with sources alongside; the laws use `include_bytes!` so no JDK is
needed at test time.

## The four laws (all GREEN, `cargo test -p j2r-classfile --lib`)

1. `round_trip_is_byte_identical` — parse→serialize equals the javac
   bytes for all 8 vectors. RED first: the writer initially emitted a
   u16 length prefix for EVERY tag; the format gives one only to Utf8
   (JVMS §4.4) — the law caught it before anything shipped.
2. `raw_reader_agrees_with_the_resolver` — this/super/interface names,
   field/method name+descriptor pairs and census agree with
   `ClassFile::parse`, and the resolver's Code bytes are a slice of the
   raw Code payload (max_stack u2 + max_locals u2 + code_len u4 prefix).
3. `retarget_this_class_rewrites_only_the_pool` — exactly one slot
   appended (the new Utf8), exactly one Class entry changed (name_index
   only), every other slot byte-identical, both member lists
   byte-identical (Code + StackMapTable ride untouched), and the output
   re-verifies: the resolver reads `remapped/RemapVec2` and the raw
   writer round-trips its own output.
4. `modified_utf8_survives_the_transport` — a hand-built pool with a
   lone surrogate (CESU-8 `ED A0 B4`) and a NUL (`C0 80`) round-trips
   bit-for-bit; the resolver loads the same class lossily (`U+FFFD`);
   `encode_modified_utf8` spells paired surrogates (U+1D54E →
   `ED A0 B4 ED B5 8E`) and `C0 80` exactly as the class file expects.
   (A &str cannot hold a lone surrogate — the encoder's contract is
   correct-by-construction; the RAW transport is the layer that must
   not normalize, and the law pins it.)
