FOLLOW-UP FOUND EN ROUTE (the fixture's first failure)

A main() that touches none of its own class's statics ran WITHOUT the
<clinit>: the generated app main never ensured the main class, so the
JVM's launcher law (JLS 12.4.2: main class initialized before main)
was unimplemented. Fix: MainInfo gains class_id + clinit_fn; BOTH main
templates (single-crate emit.rs, partitioned partition.rs) emit the
ensure line before invoking main (no-op when the class has no clinit).
Proven: ClinitPrint5/6 minimal probes (before: clinit output missing;
after: byte-identical), diff_suite 112/0 green with the change.
Registered follow-up (pre-existing, out of wave scope): clinit.rs line
`let _ = f(None, &[])` DISCARDS a clinit's Throw and marks Done — the
JLS 12.4.2 ExceptionInInitializerError / errant-class machinery is
unimplemented (no ExceptionInInitializerError anywhere in the tree;
the CyclicInit fixture pins only the in-progress-recursion law).

Registered follow-up #2 (spotted, out of scope): the pre-existing
Arrays.sort(T[], Comparator) row NPEs on a null comparator where the
JDK falls back to natural ordering (my new range-comparator row has
the JDK fallback; the old whole-array row is unchanged).
